# kIkI 개선 아이디어 노트

아직 작업 우선순위에 들어가지 않은, 검토·논의된 개선 아이디어를 적어 두는 백로그.
진행하기로 정해지면 이 문서에서 지우고 `CLAUDE.md`의 해당 Feature 절이나 실제 구현으로 옮긴다.

---

## 1. 반대 방향 한영타 감지 (한글 자판으로 잘못 친 영어 복원)

**상태**: ✅ 구현 완료(2026-09-13) — `HangulConverter.analyzeReverse()` + `TextSelectionMonitor`
방향 자동 판별. `ENGLISH_STOPWORDS` 에 `god`/`sos` 추가(사전 완전일치 방식이라 이 목록에 없는
단어는 여전히 감지되지 않음 — 필요하면 이 목록을 더 확장).

**배경**: 지금 Feature 4(한영타 교체)는 "영어 자판 상태에서 한글을 친 경우"(예: `dkssud`→`안녕`)
만 감지한다. 반대로 "한글 자판 상태에서 영어를 친 경우"는 감지하지 않는다.

- 키보드가 한글 모드인 줄 모르고 `god`를 치면 화면에는 `행`이 찍힌다
  (두벌식 매핑: g=ㅎ, o=ㅐ, d=ㅇ → 초성ㅎ+중성ㅐ+종성ㅇ = 행).
- `sos`를 치면 `낸`이 찍힌다(s=ㄴ, o=ㅐ, s=ㄴ → 초성ㄴ+중성ㅐ+종성ㄴ = 낸).
- 지금 kIkI는 이런 경우를 화면에서 잡아 되돌려주지 않는다.

**이미 있는 것**: `HangulConverter.convertKorToEng()` — 한글→영어 역변환 함수는 이미 구현돼
있고 `HangulConverterTest`로 테스트도 돼 있다. 다만 실제 감지 경로
(`TextSelectionMonitor.onSelectionChanged()` → `HangulConverter.analyze()`)에는 연결돼 있지
않아, 화면에서 이 방향의 오타를 드래그 선택해도 "교체?" 칩이 뜨지 않는다.

**구현 아이디어**: `analyze()`와 대칭인 역방향 신뢰도 판정(가칭 `analyzeReverse()`)을 추가하고,
`TextSelectionMonitor`가 두 방향을 모두 평가해 신뢰도가 더 높은 쪽으로 칩을 띄우게 한다.
`ENGLISH_STOPWORDS`처럼, 이번엔 반대 방향의 오탐 차단(흔한 한글 낱말이 우연히 영어 자판 배열에
맞아떨어지는 경우)도 별도로 검토가 필요하다.

## 2. 배지 롱프레스 → 즉시 언어 전환

**상태**: 아이디어 단계 — 설명 완료, 진행 여부 미정(2026-09-13)

**배경**: 지금 배지는 "지금 한/영 상태가 뭔지 보여주기만" 한다. 실제로 언어를 바꾸려면 키보드의
한/영 전환 키를 직접 눌러야 한다.

**제안**: 배지를 길게 누르면 kIkI가 직접 "다음 입력 방법(또는 서브타입)으로 전환"을 실행하게
한다. kIkI는 `AccessibilityService`라 `switchToNextInputMethod()` 같은 API로 실제 전환 명령을
내릴 권한이 있다.

**참고**: 원본 `radialmenu.html` 데모에는 이미 배지 롱프레스로 언어를 토글하는 `toggleLang()`
함수가 있지만(데모용으로 표시 텍스트만 바뀜), 앱 모드에서는 실제 시스템 전환에 연결돼 있지
않다. 이 아이디어는 그 데모 동작을 실제 전환으로 이어붙이는 것이다.

**검토할 것**: 기기의 IME가 서브타입을 몇 개 두고 있는지에 따라 "다음 서브타입"이 사용자가
원하는 언어로 정확히 안 넘어갈 수 있다(서브타입이 3개 이상이면 여러 번 순환 필요). 실기기
(Tab S6 Lite 등)에서 실제 동작 확인 필요.

## 3. 외장 키보드 연결/해제 피드백

**상태**: 보류 — 유선 키보드 지원 작업 때 함께 진행(사용자 지시, 2026-09-13)

**배경**: `HardwareKeyboardDetector`가 이미 외장 키보드 연결/해제를 실시간 감지하지만, 지금은
"터치 키보드 제외" 옵션의 내부 판정에만 쓰이고 사용자에게 알리지 않는다. 블루투스 키보드
배터리가 나가서 연결이 끊긴 걸 모르고 계속 입력하면 한영타가 계속 발생할 수 있다.

**제안**: 연결/해제 시 짧은 토스트나 배지 표시로 안내.

**메모**: 유선(USB) 키보드 지원 작업 시 이 감지기를 함께 손보게 될 가능성이 높으므로, 그때
같이 검토한다.

## 4. 퀵 설정 타일 (알림바 토글)

**상태**: 아이디어 단계 — 사용자 긍정적("하면 좋을듯", 2026-09-13), 구현 시작 전

**배경**: 지금 플래시/저사양 모드 등을 켜려면 앱(설정 화면)을 열어야 한다.

**제안**: `TileService`(프레임워크 API, 새 의존성 불필요 — 최소 의존성 원칙 유지)로 알림바
빠른 설정 패널에 타일을 추가해, 앱을 열지 않고 주요 기능을 토글한다.

**구현 스케치**:
- `AndroidManifest.xml`에 `<service>` 선언
  (`android:permission="android.permission.BIND_QUICK_SETTINGS_TILE"`,
  `<intent-filter>` with `android.service.quicksettings.action.QS_TILE`).
- `TileService` 서브클래스가 `Prefs`를 그대로 읽고 써서 설정 화면과 상태를 공유(별도 저장소 불필요).
- 타일 탭 시 `qsTile.state`(`Tile.STATE_ACTIVE`/`STATE_INACTIVE`) 갱신 + `updateTile()`.

**결정 필요**: 어떤 기능 하나를 타일로 노출할지(플래시 ON/OFF? 저사양 모드? 상시 배지 표시?
— 타일은 1개 앱당 여러 개 등록 가능하지만 사용자가 직접 추가해야 하는 것도 여러 개면
번거로움). 다음 진행 시 사용자에게 확인.
