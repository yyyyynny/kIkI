# 한영타 판정 실측 검증

한영타 판정(`HangulConverter.analyze`)의 규칙·파라미터는 **감이 아니라 공개 데이터 실측으로 정한다.**
이 문서는 그 데이터, 돌리는 방법, 기록된 수치를 남긴다. 규칙을 바꾸면 같은 방법으로 전후를 비교하고
아래 기록을 갱신할 것.

## 1. 데이터 받기

원본(약 55MB)은 git 기록에 영구히 남아 클론이 무거워지므로 저장소에 넣지 않는다. 출처와 SHA-256 을
`tools/eval-data/fetch.sh` 에 고정해 두었으니 언제든 같은 파일을 다시 받을 수 있다.

```bash
tools/eval-data/fetch.sh          # → tools/eval-data/data/ (.gitignore 대상), 체크섬 불일치면 경고
```

| 파일 | 출처 | 내용 | 쓰임 |
|---|---|---|---|
| `ratings_train.txt` / `ratings_test.txt` | NSMC (github e9t/nsmc) | 네이버 영화 리뷰 15만/5만 문장 | 한국어 구어체 — 감지율·한국어 쪽 오탐 |
| `train.csv` / `test.csv` | AG News (github mhjabreel/CharCnn_Keras) | 영어 뉴스 기사 12만/7.6천 | 실제 영어 글 — 오탐률 |
| `words.txt` | dwyl english-words | 영어 단어 47만(대소문자·약어 포함) | 영어 단어 — 오탐률 |

## 2. 돌리기

```bash
./gradlew testDebugUnitTest --rerun --tests "com.langsense.app.eval.*" -i   # -i 로 수치 출력
```

⚠️ `--rerun` 을 빼면 코드가 안 바뀐 경우 Gradle 이 "최신 상태"로 보고 테스트를 건너뛴다(데이터 폴더는
Gradle 이 추적하는 입력이 아니다) — 데이터를 받은 직후 수치가 안 찍히면 이것 때문이다.

`app/src/test/kotlin/com/langsense/app/eval/TypoCorpusEvalTest.kt` — 데이터가 없으면(CI 포함) 전부
건너뛰고, 있으면 아래 기준을 **단정(assert)** 한다. 임계값은 설정 기본값 70%.

| 테스트 | 무엇을 | 합격 기준 |
|---|---|---|
| `acronymTail` | 대문자 약어 + 영타 꼬리(`GUIdml`=GUI의) — 영어 쪽 같은 형태 / NSMC 약어+한글을 영타로 | 오탐 0, 감지 ≥ 90% |
| `englishNewsFalsePositive` | AG News 전체 단어 | 오탐률 ≤ 0.003% |
| `englishDictionaryFalsePositive` | 영어 단어 47만 | 오탐률 ≤ 0.05% |
| `koreanReviewsReport` | NSMC test 5만 문장 감지 수(참고용 — NSMC 에는 진짜 한영타 리뷰가 섞여 있어 단정하지 않음) | — |

### 약어+꼬리 규칙을 정한 과정 (`acronymTailConfidence`)

같은 데이터로 후보 규칙을 비교했다(오탐은 AG News+단어 목록의 `^[A-Z]{2,}[a-z]{2,}$` 1,452회,
감지는 NSMC 자리표시자 제외 2,149회).

| 규칙 | 오탐 | 감지 |
|---|---|---|
| 꼬리만 기존 모델로 채점 | 41회 (`CNNfn`×38, `WEek`, `NDak`, `FAdm`) | 93.4% |
| + 2글자 꼬리는 조사·어미로 변환될 때만 | 0 | 92.6% |
| + 구조 가산점 1.0 **(채택)** | 0 | 94.9% |
| + 구조 가산점 2.0 | 0 | 95.4% |

오탐 후보 4종이 전부 2글자 꼬리였다(`fn`→루, `ek`→다, `ak`→마, `dm`→으) — 2글자는 한 음절뿐이라
정보가 부족하므로 조사 목록으로 좁혔다. 가산점 2.0 도 오탐 0 이었지만 표본(1,452회)이 작아 보수적인
1.0 을 택했다.
