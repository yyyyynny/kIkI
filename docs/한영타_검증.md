# 한영타 판정 실측 검증

한영타 판정(`HangulConverter.analyze`)의 규칙·파라미터는 **감이 아니라 공개 데이터 실측으로 정한다.**
이 문서는 그 데이터, 돌리는 방법, 기록된 수치를 남긴다. 규칙을 바꾸면 같은 방법으로 전후를 비교하고
아래 기록을 갱신할 것.

## 0. 점수 읽는 법

판정은 토큰(공백·한글로 끊은 영문 조각)마다 두 가설을 비교한다 — "진짜 영어다" vs "한글을 영문
자판으로 친 것이다". 예: `snl`

| 입력 | 변환 | 한국어 점수 | 영어 점수 | 최종 점수 | 신뢰도 |
|---|---|---|---|---|---|
| `snl` | 뉘 | -14.96 | -25.89 | 3.64 | 76.3% |

- **한국어 점수 / 영어 점수** = 확률의 자연로그(항상 0 이하). **0에 가까울수록 흔하고, 음수가 클수록
  드물다.** 1 차이 ≈ 2.7배. 한국어 점수는 "변환 결과가 한국어 글에 나올 확률"(`뉘` -14.96, `의` -5.68 —
  뉘가 약 1만 배 드묾), 영어 점수는 "원문이 영어 단어일 확률"(`snl` -25.89 — 모음이 없어 매우 어색).
  ⚠️ 글자가 길수록 확률이 곱해져 음수가 커지므로 **같은 줄 안에서만** 비교한다.
- **최종 점수** = `(한국어 점수 − 영어 점수) ÷ 영문 글자 수`. snl: (-14.96 − (-25.89)) ÷ 3 = 3.64.
  **양수면 한영타 쪽, 음수면 진짜 영어 쪽**이 더 그럴듯하다. 글자 수로 나누는 건 긴 단어가 무조건
  유리해지지 않게 하기 위해서다.
- **신뢰도** = 최종 점수를 로지스틱 곡선으로 0~100% 로 바꾼 것. **점수 3.0 = 70% = 설정 기본 기준**
  (넘으면 "교체?" 버튼). 대략 2.0≈59%, 3.64≈76%, 4.35≈82%, 5.48≈89%.
- **예외 규칙이 끼면 같은 점수라도 신뢰도가 다르다**: 전부 대문자(`SNL`)는 약어로 보고 건너뜀(0%),
  첫 글자 외 대문자가 있으면 가산점 +2.0(`sNl` → 89.7%), 대문자 약어+꼬리(`GUIdml`)는 꼬리만 채점.
- 점수를 직접 보려면 `TypoLanguageModel.koreanLogProb(변환)`, `englishLogProb(원문 소문자)`,
  `score(원문 소문자, 변환)`, `HangulConverter.analyze(원문).confidence` 를 찍어 보면 된다.

## 1. 데이터 받기

원본(약 55MB)은 git 기록에 영구히 남아 클론이 무거워지므로 저장소에 넣지 않는다. 출처와 SHA-256 을
`tools/eval-data/fetch.sh` 에 고정해 두었으니 언제든 같은 파일을 다시 받을 수 있다.

```bash
tools/eval-data/fetch.sh          # → tools/eval-data/data/ (.gitignore 대상), 체크섬 불일치면 경고
```

| 파일 | 출처 | 내용 | 쓰임 |
|---|---|---|---|
| `ratings_train.txt` / `ratings_test.txt` | NSMC (github e9t/nsmc) | 네이버 영화 리뷰 15만/5만 문장 | 한국어 구어체 — 감지율·한국어 쪽 오탐 |
| `train.csv` / `test.csv` | AG News (github mhjabreel/CharCnn_Keras) | 영어 뉴스 기사 12만/7.6천 | 실제 영어 글 — 오탐률 |
| `words.txt` | dwyl english-words | 영어 단어 47만(대소문자·약어 포함) | 영어 단어 — 오탐률 |

## 2. 돌리기

```bash
./gradlew testDebugUnitTest --rerun --tests "com.langsense.app.eval.*" -i   # -i 로 수치 출력
```

⚠️ `--rerun` 을 빼면 코드가 안 바뀐 경우 Gradle 이 "최신 상태"로 보고 테스트를 건너뛴다(데이터 폴더는
Gradle 이 추적하는 입력이 아니다) — 데이터를 받은 직후 수치가 안 찍히면 이것 때문이다.

### 약어+꼬리 규칙을 정한 과정 (`acronymTailConfidence`)

같은 데이터로 후보 규칙을 비교했다(오탐은 AG News+단어 목록의 `^[A-Z]{2,}[a-z]{2,}$` 1,452회,
감지는 NSMC 자리표시자 제외 2,149회).

| 규칙 | 오탐 | 감지 |
|---|---|---|
| 꼬리만 기존 모델로 채점 | 41회 (`CNNfn`×38, `WEek`, `NDak`, `FAdm`) | 93.4% |
| + 2글자 꼬리는 조사·어미로 변환될 때만 | 0 | 92.6% |
| + 구조 가산점 1.0 **(채택)** | 0 | 94.9% |
| + 구조 가산점 2.0 | 0 | 95.4% |

오탐 후보 4종이 전부 2글자 꼬리였다(`fn`→루, `ek`→다, `ak`→마, `dm`→으) — 2글자는 한 음절뿐이라
정보가 부족하므로 조사 목록으로 좁혔다. 가산점 2.0 도 오탐 0 이었지만 표본(1,452회)이 작아 보수적인
1.0 을 택했다.

## 4. 남은 과제 (발견만 하고 아직 안 고친 것)

- **소문자 약어 `snl`(SNL) → "뉘" 오탐**: NSMC test 에서 2문장("딱 snl 수준" 등). 점수 3.64(76.3%).
  영어 모델이 **단어**로 학습돼 모음 없는 약어를 못 알아본다(영어 -25.89). 같은 이유로 `sns`→눈도
  3.46(74.6%) 감지 — 일상 글에선 이쪽이 더 흔할 것. 둘 다 변환 결과가 **한 음절**이라 정보가 부족한
  경우다(2글자 제외 규칙과 같은 사유).
- **중간 대문자 가산점이 Shift 무의미 키에도 붙는다**: 두벌식에서 Shift 가 의미 있는 키는
  Q·W·E·R·T·O·P 뿐인데 `sNl` 의 N 에도 +2.0 → 89.7%. 오히려 한영타가 아니라는 증거여야 한다.
- **CapsLock 을 켠 채 친 한영타는 사실상 미지원**: `DKSSUD`(안녕)·`WJDAKF WHGEK`(정말 좋다)는 전부
  대문자라 약어로 보고 0%, `GOtEK`(했다) 32%. 게다가 `GKArP`(함께)는 위 가산점 때문에 90% 로 잡히는데
  교체가 CapsLock 을 몰라 **"GKA계"로 망가뜨린다**. 대소문자를 뒤집어 다시 판정하면 되지만, 전부
  대문자 규칙이 막고 있던 약어 오탐(`SNS`/`DLC`/`EJSM` → 뒤집으면 한글처럼 보임)이 다시 열리므로 데이터로
  경계를 정해야 한다.
